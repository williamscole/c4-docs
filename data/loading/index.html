    Loading and merging¶

    Open a cohort¶

    from c4.cohort import cohort

demo = cohort("demo")

    Cohort names are case-insensitive, and aliases work too (cohort("DEMO")). Opening a cohort prints everything the catalog knows about it:

    Cohort: demo (DEMO)    owner: A. Researcher
Catalog: c4/catalog.yaml    root: /data/lab

Loadable with .load():
  name                      id                 params                                         status
  ────────────────────────  ─────────────────  ─────────────────────────────────────────────  ──────
  id_map                    -                                                                 ✓
  pheno.main *              patient (ID)                                                      ✓
  pcs                       array (IID)                                                       ✓
  hla.hlahd.standardized *  exome (seqID)                                                     ✓
  hla.hibag.raw *           array (sample.id)  panel: european*, african, asian, multiethnic  3/4 ✗

Genetic data, use .path():
  name         format  build  params             status
  ───────────  ──────  ─────  ─────────────────  ───────
  dna.imputed  vcf     b38    chrom: 1..22 (22)  22/22 ✓
  dna.exome    -       -                         not set

* default: "pheno" -> pheno.main, "hla.hlahd" -> hla.hlahd.standardized, "hla.hibag" -> hla.hibag.raw

    How to read it:

    • name is what you pass to .load() or .path(). A * marks a default: "pheno" on its own loads pheno.main (see the footnote).
    • id is the kind of ID the table uses and the column it is in. This is how the table gets linked to patients (How IDs link).
    • params are the values a templated file takes, with the default marked *. Long lists are shortened (1..22 (22)).
    • status: ✓ all files found · ✗ missing · 3/4 ✗ some of a templated file's variants are missing · not set the catalog has TODO for this path.

    The table prints again whenever you display the object (demo on its own line in a notebook, or print(demo)). Pass show=False to cohort() to skip it.

    Every loaded table comes back as a pandas DataFrame with two columns added at the front:

    • patient_id, looked up from the table's own ID column through the cohort's ID map. The original ID column (ID here) is kept.
    • qc_note, from the ID map: why a patient was flagged during sample QC, or blank. See QC notes below.

    Tables keyed by a genetic ID are linked the same way. The PC file uses array IDs:

    Templated files¶

    Some catalog entries stand for several files, one per value of a parameter. HIBAG calls, for instance, exist for each reference panel. Pass the parameter by name:

    hibag = demo.load("hla.hibag", panel="african")

      patient_id qc_note sample.id    A_1    A_2  prob_A
0       P001     NaN  ARR-0001  02:01  24:02    0.97
1       P002     NaN  ARR-0002  01:01  03:01    0.99
2       P003     NaN  ARR-0003  11:01  24:02    0.88
3       P004     NaN  ARR-0004  02:01  02:01    0.95
4       P007     NaN  ARR-0007  30:01  33:03    0.71

    Leave the parameter out and its default is used (european here). An invalid value raises an error that lists the valid ones.

    HIBAG columns

    Raw HIBAG output has columns like allele1_A and allele2_A. The HIBAG loader renames them to A_1 and A_2, the split-allele naming used elsewhere in c4. prob_A is kept as is.

    Merge tables¶

    Give .load() several names and the tables are merged on patient_id:

    df = demo.load("pheno", "pcs", "hla.hlahd")

    Note: 1 of 7 rows in 'pcs' have no patient_id (array ID not in id_map).
  pheno.main                      8 patients
  (1 row(s) of pcs without a patient_id dropped before merging)
+ pcs                             6 matched   (2 without)
+ hla.hlahd.standardized          6 matched   (2 without)
= 8 rows (left join on patient_id)

    df[["patient_id", "qc_note", "OS_mo", "IID", "PC1", "seqID", "A"]]

      patient_id                                       qc_note  OS_mo       IID    PC1    seqID              A
0       P001                                           NaN   31.2  ARR-0001  0.012  EX-0001  A*02:01/24:02
1       P002                                           NaN   44.0  ARR-0002  0.010  EX-0002  A*01:01/03:01
2       P003                                           NaN   12.5  ARR-0003 -0.044  EX-0004  A*11:01/24:02
3       P004                                           NaN   27.9  ARR-0004  0.009  EX-0003  A*02:01/02:01
4       P005                                           NaN   50.1       NaN    NaN  EX-0005  A*03:01/68:01
5       P006  sex mismatch (genetic male, recorded female)    8.4  ARR-0006  0.013  EX-0006  A*01:01/02:01

    The PCs and HLA calls came from different ID systems (array and exome), but both landed on the right patients. Notice that P003 got exome EX-0004 and P004 got EX-0003: those two samples were swapped at sequencing, and the ID map corrects it (How IDs link).

    What the merge does¶

    • Starts from the first table and adds the others with a left join, so every row of the first table is kept. Put the table that defines your study population first (usually "pheno"). Use how="inner" to keep only patients present in every table, or how="outer" for everyone.
    • Prints a report: how many patients each table matched and how many it didn't. Read it. It is the quickest way to notice that a table covers far fewer patients than you expected. verbose=False turns it off.
    • Drops rows with no patient_id (like the control sample above) before merging, since they can't be joined, and says how many.
    • Refuses to merge a table with more than one row per patient. Duplicate patients would silently multiply rows in the result, so instead you get an error naming the patients. Load that table on its own to look at it.
    • Prefixes clashing column names. If two tables share a column name (other than patient_id), the later table's copy gets a prefix, e.g. pcs.site. The first table keeps its names. The report lists any prefixed columns.

    Parameters apply to whichever tables use them:

    demo.load("pheno", "hla.hibag", panel="asian")

    QC notes¶

    The ID map can carry a qc_note for patients flagged during sample QC (a sex mismatch, an unresolved identity problem). By default it is added to every loaded table so you can see it. Two options:

    demo.load("pheno", exclude_flagged=True)   # drop patients with any qc_note
demo.load("pheno", qc_note=False)          # don't add the column

    Excluded 1 row(s) with a qc_note.

    Flagged patients are kept unless you ask

    .load() never drops flagged patients on its own. Decide per analysis, and use exclude_flagged=True when flagged samples shouldn't be used.

    Genetic data¶

    VCF and PLINK files aren't tables you load into pandas; you hand them to bcftools, plink or the c4 commands. .path() gives you the file:

    demo.path("dna.imputed", chrom=6)

    /data/lab/demo/dna/chr6.dose.vcf.gz

    .paths() gives every variant of a templated entry, keyed by parameter value, which makes per-chromosome loops easy:

    import subprocess

for chrom, vcf in demo.paths("dna.imputed").items():
    subprocess.run(["bcftools", "index", "-n", str(vcf)], check=True)

    The sample names inside a genetic file are IDs of that data type (imputed IDs for dna.imputed). To connect them to patients, use the ID map:

    ids = demo.id_map()                                  # the full table
to_patient = dict(zip(ids["imputed_id"], ids["patient_id"]))

    Data dictionary¶

    If a phenotype table has a data dictionary in the catalog, .describe() looks up columns:

    demo.describe("OS_mo")

    Overall survival (months) (numeric)

    Lookups are case-insensitive, and a near miss suggests the closest match:

    demo.describe("os_months")

    Column 'os_months' not found. Did you mean: 'OS_mo'?

    Several columns print as a table:

    demo.describe("age", "female", "OS_event")

    +----------+------------------------------------------+
| Column   | Definition                               |
+----------+------------------------------------------+
| age      | Age at treatment start (years) (numeric) |
| female   | 1 = female, 0 = male (binary)            |
| OS_event | 1 = death, 0 = censored (binary)         |
+----------+------------------------------------------+

    describe uses "pheno" by default; pass table= with any other phenotype entry that has a data dictionary.

    Check the catalog¶

    .check() walks every entry and reports anything that doesn't line up: missing files, paths still marked TODO, ID columns that aren't in the file, and ID map problems.

    problems = demo.check()

    demo: 2 problem(s)
  ✗ dna.exome: path not set (TODO)
  ✗ hla.hibag.raw: 1 of 4 file(s) missing, e.g. /data/lab/demo/hla/hibag_multiethnic.csv

    It also returns the problems as a list (empty when everything is fine), so a script can fail on them. Run it after editing the catalog or moving data.
